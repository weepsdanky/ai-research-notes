三分钟定位“移动马赛克”

今天只学一个技能：不要问“模型为什么坏了”，而要问“坏在 VAE、denoiser、condition，还是 sampler 的哪条边界？”

当前已通过

VAE 重建仍看得见猫；MP4 的相邻帧确实变化；数值 finite；337 个实现测试通过。

当前未通过

从纯噪声恢复语义；C1 动作为 0/28；CLIP matched 与 shuffled 都是 15.4%。

所以故障在哪里？

真实 RGB → VAE latent ✓ → 加噪/denoiser/condition/sampler ✗ → VAE decode → 移动马赛克

VAE 可以显示结构，但模型没有生成出带结构的 latent。下一步应对真实 latent 分别加到 t=100、500、900、999，再从该处还原；第一个失败的 timestep 就把故障范围缩小了。

这次最可疑的配置：12×12 latent / patch 3 = 每帧仅 4×4 token。每个 token 横跨约 24×24 输出像素，主体轮廓很容易被压成粗色块。

检索练习

VAE 重建清楚、纯噪声生成模糊，应该先更换 VAE 吗？

不应该。先检查 denoiser 在不同噪声等级的重建以及 sampler；VAE 已提供了一个可辨识上限。

训练 loss 继续下降，是否足以决定再训练 30k？

不足。必须看高噪声 bucket、固定 seed 自由生成和文本交换；总 loss 会把关键失败平均掉。

下一次最小、信息量最大的架构变更是什么？

单 clip 下只把 patch 1→2→3，其余完全固定；它能直接检验空间 token 是否过粗。

一手阅读从 DDPM 的 q-sample/reverse step 开始，再读 DiT 的 patchify 与 adaLN-Zero；完整顺序见行动文档，速查见排查阶梯。不清楚的地方继续问我。
