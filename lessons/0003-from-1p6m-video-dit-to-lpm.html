从 1.6M Video DiT 到 LPM

今天只学一个判断技能：区分“训练闭环已通过”“小数据已记住”和“模型容量已到上限”。你当前只证明了前两项。

已经学到

3D latent、空间/时间 attention、文本 token 条件、epsilon diffusion、CFG、EMA、真实视频训练、分噪声诊断，以及从移动马赛克恢复到可辨识生成。

尚未证明

8–10 clip 扩展、held-out prompt/组合泛化、身份保持、音频时序对齐、长时滚动、flow matching、因果流式生成和大规模分布式训练。

1.6M 是不是上限？

不是模型上限。当前最佳模型只在三条训练视频上通过可辨识门禁；海滩上的狗仍弱。它证明 1.6M 足以记住并区分三个局部分布，不证明其在更多数据上已经达到不可改善的容量极限。

系统规模相对 1.6M它说明什么

Latte-S32.48M约 20×公开论文中的最小视频配置也大一个数量级

下一道门：先泛化，不先放大

Gate 1 · 训练集记忆三条训练 prompt 可辨识。当前已过。
Gate 2 · 数据扩展扩到 8–10 clips，保持每 clip 暴露、token 数、采样协议一致。若变回马赛克，说明 scratch 空间先验/容量/数据效率不足。
Gate 3 · 未见组合主体、动作、场景三因素拆分；训练不包含某个组合，测试该 held-out triple。必须做盲评，不能只看总 loss。
Gate 4 · 预训练迁移若 Gate 2/3 失败，不继续暴力训练 1.6M；加载预训练 image/video latent prior，冻结空间块或主干，只训练 temporal blocks、text/audio adapter。

学习顺序

泛化实验 → 预训练空间先验迁移 → Flow Matching → 音频时间对齐与多参考身份 → 因果 chunk / rollout → 蒸馏 → 分布式基础设施

Flow Matching 是现在最合适的下一门数学课：它仍在单机可控范围内，又直接连接 LPM Base Model 的训练目标。音频、多参考与流式生成应在一个更可靠的视觉先验上学习，否则无法区分“视觉生成失败”和“条件没对齐”。

什么时候学习 LPM 的大规模训练问题？

现在先概念性阅读，等本地单卡实验出现对应症状再动手实现：

问题现在触发实作的时机
token bucket / 数据负载均衡理解原因开始混合分辨率、帧数、时长
activation checkpoint / mixed precision可先实验显存限制阻止增大 token 或 batch
FSDP / HSDP只读模型或 optimizer state 放不进单卡
Ulysses context parallel只读序列达到数万 token，单卡 attention 无法容纳
流式 train–inference mismatch先做 toy chunk开始 causal rollout，误差随 chunk 累积
DMD / on-policy distillation后学已有强离线 teacher，目标变成少步实时学生
下一次实验只回答一个问题：同一个 1.6M checkpoint/recipe 扩到 8–10 clips，在匹配每 clip 暴露后是否仍可辨识，并能否通过至少一个 held-out 组合？答案出来以前，不宣称容量上限，也不开始 17B 式基础设施。

检索练习

训练 loss 继续下降且出现猫，是否证明模型容量用尽？

否。它只证明训练分布拟合；容量上限需要数据规模、模型规模与计算预算的受控 scaling sweep，并看 held-out 指标。

为什么不马上加入音频条件？

视觉先验尚未通过泛化门禁。此时失败无法归因于视觉 denoiser 还是音频对齐，增加条件只会扩大诊断空间。

LPM 的 DMD 应该什么时候学？

在已有强离线 teacher、理解 Flow Matching，并实际遇到因果少步 student 的 rollout distribution shift 之后。
